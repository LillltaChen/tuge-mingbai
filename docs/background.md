# 图个明白 — 项目背景

> 一个从「看见好图却写不出提示词」的真实痛点中生长出来的 Chrome 扩展。

---

## 一、缘起：一个反复出现的场景

2024 年，AI 绘图工具（Midjourney、Stable Diffusion、DALL·E）已经进入创作者的日常 workflow。但几乎每一个使用者都经历过这样的时刻：

> 刷 Pinterest、逛 ArtStation、看小红书时，突然看到一张惊艳的图——光影、构图、色调都恰到好处。心里涌起一个念头：「这张图如果用 AI 做出来，提示词该怎么写？」

于是开始了经典的「折腾五步曲」：

1. **截图** — 用系统截图工具框选图片
2. **打开 ChatGPT/Claude** — 切到另一个标签页或 App
3. **上传 + 打字** — 「请分析这张图，生成 Midjourney 提示词」
4. **等待 + 调整** — AI 返回一段文字，往往格式混乱、中英混杂
5. **复制粘贴** — 把结果拷贝到绘图工具的输入框

整个过程**超过 2 分钟**，且伴随着频繁的上下文切换。更糟的是，当你想批量分析一组风格统一的参考图时，这个流程会重复 N 次，效率极低。

这个场景反复出现，足够痛、足够高频，却没有人做一个「右键即达」的轻量工具来解决它。

---

## 二、痛点拆解

### 🔴 核心痛点：图片→提示词的转化链路太长

| 环节 | 问题 | 成本 |
|------|------|------|
| 获取图片 | 截图、保存、上传，多一步操作 | ~20s |
| 切换应用 | 离开当前页面，打断心流 | ~10s |
| 描述需求 | 每次都要打字说明「分析这张图生成提示词」 | ~15s |
| 结果整理 | AI 返回大段文字，需要手动提取有效信息 | ~30s |
| 格式调整 | 中英文混杂、没有结构，需要二次编辑 | ~45s |

**单次成本 ≈ 2 分钟，高频用户一天可能重复 10-20 次。**

### 🟡 衍生痛点

1. **提示词质量不稳定**
   - 不同 AI 模型返回的格式差异大，有的像散文、有的像标签云
   - 没有统一的结构化输出（英文 Prompt + 中文说明 + 风格标签）

2. **缺乏历史回溯**
   - 昨天分析过的一张图，今天想再参考，找不到了
   - 没有「我的灵感库」概念

3. **批量处理困难**
   - 做一套风格统一的素材时，需要一张张分析
   - 没有队列管理和进度可视化

4. **双语需求割裂**
   - 英文平台（Midjourney/Discord）需要英文 Prompt
   - 中文社区分享需要中文解释
   - 两者需要手动互译，容易失真

---

## 三、解决方式：把链路压缩到「右键 → 1 秒」

### 核心设计原则

> **「所见即所得，右键即分析」**
>
> 用户不需要离开当前页面，不需要上传文件，不需要打字描述需求。

### 产品架构

```
用户右键点击图片
    │
    ▼
扩展自动提取图片 URL → 转为 base64
    │
    ▼
调用 GPT-4o Vision API 分析图像内容
    │
    ▼
返回结构化 JSON：{english, chinese, style, tags}
    │
    ▼
在页面内以浮窗形式直接展示结果
    │
    ▼
一键复制 / 点击标签复制 / 实时编辑同步翻译
```

**全链路时间：3-8 秒（含 API 响应）**

### 关键设计决策

| 决策 | 理由 |
|------|------|
| **Chrome Extension 形态** | 浏览器是图片消费的天然场景，扩展可以无缝嵌入右键菜单 |
| **Manifest V3** | 符合 Chrome 商店最新规范，Service Worker 架构更轻量 |
| **纯 Vanilla JS** | 无框架依赖，扩展体积 < 100KB，加载零延迟 |
| **页面内浮窗（而非弹窗）** | 不离开当前页面，不打断浏览心流，可拖拽缩放 |
| **JSON 结构化输出** | 让 AI 返回标准格式，前端统一解析展示，结果可控 |
| **本地 LRU 缓存** | 20 条历史记录存 chrome.storage.local，重复图片秒出结果，节省 Token |
| **批量队列系统** | 支持多张图片并行/串行分析，带进度面板和状态管理 |
| **中英实时同步** | 编辑提示词时自动调用 API 翻译，800ms debounce，避免频繁请求 |

## 四、产品价值主张

### 对 AI 绘图创作者

- **省时间**：单次分析从 2 分钟 → 5 秒，一天节省 30 分钟以上
- **提质量**：结构化提示词 + 风格标签，直接可用，无需二次整理
- **建灵感库**：历史记录自动保存，随时回顾已分析的参考图

### 对设计师/视觉从业者

- **快速拆解风格**：看到好图，立刻知道「光线怎么打」「色调怎么调」「构图怎么排」
- **批量收集素材**：一组风格统一的参考图，批量分析后统一归档

### 对 AI 工具初学者

- **降低门槛**：不需要学习复杂的提示词语法，看图就能学会怎么描述
- **双语对照**：中文理解画面，英文直接复制到绘图工具

## 五、差异化：为什么是这个产品？

市面上并非没有「图片反推提示词」的工具，但它们的体验普遍停留在「工具」层面，而非「workflow 的一部分」：

| 现有方案 | 问题 | 图个明白的改进 |
|---------|------|--------------|
| 在线网页工具（如 PromptHero） | 需要上传图片、离开当前页面 | 右键即用，不离页 |
| Discord 机器人 | 需要在 Discord 内操作，格式受限 | 浏览器原生体验，格式自由 |
| 桌面端 AI 工具 | 需要安装 heavyweight 软件 | 浏览器扩展，< 100KB |
| 油猴脚本 | 功能简陋、无 UI、不稳定 | 完整浮窗面板、缓存、队列、主题切换 |
| 直接问 ChatGPT | 每次打字描述需求、结果格式不一致 | 一键触发、JSON 结构化、可编辑同步 |

**核心差异：不是「多了一个工具」，而是「减少了一层阻碍」。**

用户不需要「打开某个东西来做某事」——他们只是在正常浏览网页，右键一下，答案就出现了。

## 六、设计哲学

### 1. 隐形的工具

好的工具应该像空气一样存在——你需要它的时候它在，不需要的时候完全不打扰。图个明白没有常驻 UI，没有通知推送，只有在右键菜单里静静等待的那一行字。

### 2. 愉悦的细节

- AI 分析时的「扫描动画」——模糊呼吸、扫描线、角点脉冲、打字机文字
- 复制按钮的涟漪反馈
- 拖拽时的弹性阴影
- 明暗主题的丝滑切换

这些细节不会让工具「更快」，但会让用户「更愿意用」。

### 3. 尊重隐私

- API Key 和历史记录**只存在本地浏览器**
- 不上传任何数据到第三方服务器
- 用户对自己的数据有完全控制权

## 七、技术选型背后的思考

### 为什么不用 React/Vue？

扩展的 content script 注入到每一个网页，框架体积（即使压缩后几十 KB）会增加页面负担，且可能与宿主页面的框架冲突。Vanilla JS 手写虽然代码量大，但**完全可控、零依赖、零冲突**。

### 为什么选 OpenAI Vision API？

- **理解精度**：GPT-4o 对图像的风格、构图、光影、情绪有极强的描述能力
- **输出可控**：通过 system prompt 约束返回 JSON 格式，结果结构化
- **生态兼容**：支持任意 OpenAI 兼容接口（Gemini、Claude、自托管模型均可接入）

### 为什么做本地缓存而非云端？

- 减少 API 调用成本（重复图片不花钱）
- 保护用户隐私（图片 URL 不出本地）
- 即时响应（缓存命中时 < 100ms 出结果）

## 九、写在最后

> **「图个明白」不是为了替代 AI 绘图工具，而是为了消除「从看到一张图到画出一张图」之间的阻碍。**

它不是最复杂的工具，也不是功能最多的工具。它只是在一个足够痛、足够高频的场景里，做了一个足够简单、足够优雅的解法。

希望每一个用过它的人，在右键点击那张让你心动的图片时，能轻轻说一句：

> **「哦，原来这张图是这么画出来的。」**
